# ir-deck

정부지원사업·초기 투자용 IR 덱과 사업계획서를 심사역이 읽기 좋은 기준으로 **새로 만들거나 점검하는** Claude Code 스킬입니다.

심사역은 하루에 덱을 수십 개 읽습니다. 그래서 이 스킬의 기준은 한 가지를 겨냥합니다. 제목만 훑어도 사업이 이해되고, 숫자를 의심했을 때 바로 옆에 근거가 있을 것.

## 하는 일

| 일 | 언제 쓰나 | 나오는 것 | 더 필요한 것 |
|---|---|---|---|
| 만들기 | 사업계획서나 메모가 있을 때 | 12쪽 원고, 숫자 장부, 고칠 점과 숙제 목록 | 없음 |
| 점검 | 이미 덱이나 사업계획서가 있을 때 | 점검 항목 81개의 통과·미흡, 고친 문장, 어긋난 숫자 | 없음 |
| 가설 덱 | 아이디어만 있을 때 | 모의 결과로 채운 제출용 아닌 덱과, 무엇을 실제로 재야 하는지 적은 바꿈표 | founder-skill |

만들기와 점검은 이 스킬만으로 됩니다. 가설 덱만 [founder-skill](https://github.com/Jakeschincariol/founder-skill)을 같이 씁니다.

## 기준

1. **제목이 결론이다.** 큰 제목은 "~습니다"로 끝나는 한 문장이고 숫자를 하나 이상 넣습니다. 제목 12개만 이어 읽어도 발표가 됩니다.
2. **숫자마다 꼬리표를 단다.** 출처, 기준, 계산식을 붙이고 직접 계산한 값은 `[추정]`, 앞으로 이룰 값은 `[목표]`로 표시합니다.
3. **용어는 정확히, 꾸밈은 없이 쓴다.** PoC, 트랙션, GTM 같은 용어는 뜻에 맞게 쓰고 처음 나올 때 풀이를 붙입니다. 혁신적, 압도적 같은 말은 쓰지 않습니다.
4. **약한 점을 먼저 말한다.** 경쟁사가 앞서는 칸과 확정되지 않은 것을 그대로 적습니다.
5. **작게 시작해 넓힌다.** 타깃 고객을 한 문장으로 좁히고 첫해 숫자를 할 수 있는 크기로 적습니다.

여기에 두 가지 점검이 더 있습니다.

- **지어내지 않는다.** 자료에 없는 숫자, 출처, 고객의 말은 채우지 않고 `[확인 필요]`로 남깁니다.
- **줄거리가 이어지는지 본다.** 숫자가 다 맞아도 장과 장 사이가 끊기면 설득이 안 됩니다. "쓰는 사람과 돈 내는 사람이 같은가" 같은 고리 아홉 개를 하나씩 확인합니다.

## 쓰는 법

Claude Code에서 평소 말로 요청하면 됩니다. 스킬 이름을 말하지 않아도 됩니다.

- "예비창업패키지 발표가 다음 주야. 첨부한 사업계획서 초안으로 IR 덱 원고 만들어 줘."
- "이 IR 덱 심사 기준에 맞는지 봐 줘. 숫자도 맞는지 확인해 줘."
- "아이디어만 있는데 가설 덱 만들어 줘."

## 가설 덱

아이디어만 있고 고객도 숫자도 없을 때 쓰는 방식입니다. 가설이 다 맞다고 치고 12쪽을 끝까지 써 본 뒤, 무엇을 실제로 재야 하는지를 거꾸로 뽑습니다.

네 줄(무엇을, 누구에게, 얼마에, 어디서)을 받고, 세 관점의 검토 → 경쟁사 조사 → 모의 구매자 패널 → 손익 계산 순서로 재료를 만든 뒤 덱을 씁니다. 재료를 만드는 데는 [founder-skill](https://github.com/Jakeschincariol/founder-skill)(Jake Schincariol, MIT)을 씁니다. 이 저장소에는 들어 있지 않으니 따로 설치해야 합니다. 설치돼 있지 않으면 가설 덱 대신 일반 "만들기"로 진행합니다.

### founder-skill 설치

```bash
git clone https://github.com/Jakeschincariol/founder-skill.git
```

```bash
cp -r founder-skill/skills/founder-* ~/.claude/skills/
```

파이썬 3.8 이상이 필요하고 따로 설치할 패키지는 없습니다. 플러그인으로 설치하면 스킬 이름 앞에 꼬리표가 붙으므로, 가설 덱과 같이 쓸 때는 위처럼 폴더째 복사하는 쪽을 권합니다. 다른 사람이 만든 스킬이니 설치 전에 저장소를 한 번 확인하세요.

가설 덱이 쓰는 것은 다섯 개입니다.

| 스킬 | 가설 덱에서 하는 일 |
|---|---|
| `founder-board` | 아이디어를 세 가지 관점으로 따져 보고 위험을 뽑는다 |
| `founder-competitors` | 경쟁 서비스와 가격을 링크와 함께 찾는다 |
| `founder-consumer` | 가상 구매자에게 소개 문구를 보여 주고 살지 묻는다 |
| `founder-cfo` | 한 건당 남는 돈과 손익분기를 계산한다 |
| `founder-launch` | 모의 결과를 대신할 실제 시험을 고른다 |

가설 덱은 제출용이 아닙니다.

- 모의 패널의 숫자에는 `[모의]`가 붙고, PoC나 트랙션이라고 부르지 않습니다.
- `[모의]`가 하나라도 남아 있으면 판정은 "제출 불가"입니다.
- 보고에 바꿈표가 실립니다. `[모의]`마다 그것을 대신할 실제 시험과 성공 기준을 적습니다.
- 모의 패널은 인원수만큼 서브에이전트를 부릅니다. 20명 기준으로도 토큰이 많이 듭니다.

## 알고 쓸 것

- **기준의 출처.** 기준은 심사역이 좋게 본 자료로 전달받은 실제 IR 덱에서 뽑았습니다. 그 덱의 내용은 이 스킬에 싣지 않았고, 예시는 모두 지어낸 가상의 회사입니다. 한정된 자료에서 뽑은 기준이라 모든 심사에 맞는 정답은 아닙니다. 지원 공고의 평가 항목이 있으면 그것이 우선입니다.
- **모의는 증거가 아니다.** 가설 덱의 모의 패널은 AI가 연기한 가상 구매자입니다. 무엇을 물어볼지 정하는 데 쓰고, 실제 고객으로 바꿔야 합니다.
- **통계는 다시 확인한다.** 스킬은 웹에서 원문을 찾아 확인하도록 되어 있지만, 발표 전에 출처를 직접 열어 보세요.
- **조언이 아니다.** 투자, 법률, 세무 조언이 아닙니다.
